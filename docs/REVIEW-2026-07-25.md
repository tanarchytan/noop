# noop-tan code review — 2026-07-25

Same pass as `whoop-rs/dev-docs/review-2026-07-25.md`: algorithm errors, dead code, duplicate logic,
layout. 302 Kotlin files / 109k lines, so this was driven by tooling rather than reading.

State after the pass: **2401 tests, 0 failed, 3 skipped; APK builds; 7 compiler warnings (all benign).**

## Fixed

- `VitalityEngine.Result.deltaYears` -> `advanceYears`, sign flipped. It was `chronoAge - bodyAge`
  (positive = *younger*), the opposite of `rhythm_age` and `fitness_age`. Vitality itself still reads the
  "years younger" direction internally; only the exposed field changed. Tests updated to assert the
  direction by name.
- Deleted three orphans with zero references anywhere: `ThreeDaySelectorBar`, `SparkTailBox`
  (Composables nothing renders) and `setJournalItemSortIndex` (its two siblings are used).
- Body Clock wired to the Rust cosinor + the Kotlin twin deleted (see the whoop-rs review).

## The real finding: 9 shipped Rust functions the app never calls

`whoop-ffi` exports 56 functions. Nine are wired through uniffi, compiled into both `.so`, and **never
called from Kotlin** — because a Kotlin twin is still doing the work:

| unused FFI export | Kotlin still doing it | size |
|---|---|---|
| `workout_detect` | `WorkoutDetector.kt` (called at `AnalyticsEngine.kt:543`) | 522 lines |
| `imu_features` | `ImuFeatureExtractor.kt` | 97 lines |
| `calories_estimate_bout` | `ActivityCostEngine.kt` | 307 lines |
| `baseline_fold_history`, `baseline_metric_cfg_hrv` | `Baselines.foldHistory` (the per-night `baselineUpdate` DOES go to Rust) | partial |
| `hrv_sdnn` | `HrvAnalyzer.sdnnRaw` | one function |
| `hrv_readiness`, `spo2_from_paired`, `haptic_clock_pulses` | no caller either side | — |

**MIGRATED — 9 unused exports down to 4.** Each engine was swapped to the Rust path and the Kotlin
maths deleted; the existing absolute-value tests are the parity proof (they pin figures produced by the
old Kotlin and still pass against Rust).

| engine | before | after | parity gate |
|---|---:|---:|---|
| `WorkoutDetector.kt` | 522 lines | 75 | `WorkoutDetectorTest` 4/4, `SedentaryDetectorTest` 17/17 |
| `ImuFeatureExtractor.kt` | 97 | 48 | `ImuFeatureExtractorTest` 5/5 |
| `Calories` (bout energy) | in WorkoutDetector | adapter | `ActivityCostEngineTest` 14/14 |
| `HrvAnalyzer.sdnnRaw` | local SD | adapter | full suite |
| `Baselines.foldHistory` | local loop | adapter | full suite |

Two FFI exports were ADDED so the migration lost nothing: `WorkoutSession` now carries `hrmax` +
`hrmax_source` (the Kotlin `ExerciseSession` needs them and the FFI record was dropping them), and
`activity_series` / `smoothed_intensity` are exported so the sedentary + nap motion spine is the same
one the workout detector measures against.

**The border after the pass:** `RustScores.kt` is the single seam — one thin adapter per engine, no
arithmetic. `WorkoutDetector`, `ImuFeatureExtractor`, `Calories`, `Baselines` and `HrvAnalyzer` keep
their app-shaped doors (profile defaults, `UserProfile`, the recalibration-epoch overload, the frames
overload) and delegate the maths. Frontend-owned policy stays in Kotlin: the baseline recalibration
epoch, the profile fallbacks, and the wording.

**Still unused, and correctly so:** `hrv_readiness`, `spo2_from_paired`, `haptic_clock_pulses` have no
caller on either side (unused features, not shadowed algorithms); `baseline_metric_cfg_hrv` is a
convenience constructor the Kotlin `metricCfg` map supersedes.

## Parked, with reasons

- **Two half-built features, evidenced by dead entry points.** `startOrResumeLiveSession` (LiveSessionScreen.kt)
  is the only way to begin a Live Session and nothing calls it, though `LiveSessionRunner` /
  `LiveSessionEngine` / `LiveSessionScreen` all exist. `saveCustomJournalQuestions` /
  `saveHiddenJournalQuestions` are the only writers for two lists whose readers ARE used, so those lists
  can never be populated. Deleting the dead half would erase the scaffold and hide the missing wire, so
  both are left in place and reported instead.
- `DebugExportWorker` / `DebugExportScheduler` — carries a written "kept as a dormant scaffold; restore
  the enqueue path here" note. Intentional.
- The 7 compiler warnings: an unused log-line parameter (`subScoreLine`'s `inBedSeconds`), an unused
  `when` binding (`DataBackup` `staged`), and Composable/interface signature params. None are defects.
  `AnalyticsEngine`'s `sleepNeedNights` is documented as driving the Rest confidence tier but is unused
  in that function — worth a look, but not something to change blind.
